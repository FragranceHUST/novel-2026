# 互联网 / 量化 / AI Infra：技术工种职业发展路线与能力迁移分析

> **适用对象**：在这三个行业之间做选择、或计划跨行业迁移的技术工程师（约 0–12 年经验）。
> **使用方式**：第 1–2 节是坐标系，后面所有结论都建立在这上面，建议先读；第 3–5 节是分行业路线图；第 6–8 节是跨行业迁移的核心结论（本文最有价值的部分）；第 9–12 节是时间规划、决策与自检；附录 A 是可执行的 12 个月计划，附录 B 是岗位甄别清单。
> **口径说明**：年限、薪资、职级均为中国大陆一线/新一线市场 2024–2026 年的经验区间，用于判断"量级与结构"，不是精确报价；薪资含股票/期权与分成的差异很大，文中只给结构不给承诺。所有权重与复用率百分比是分析性估计，用来表达相对关系，不是测量值。

## 1. 底层坐标系：三个行业对"能力"的定价函数不同

同一个工程师，能力不变，换个行业"值多少钱"可能差 2 倍。原因不是能力变了，而是**行业对能力的定价函数不同**。

| 维度 | 互联网 | 量化 | AI Infra |
|---|---|---|---|
| 价值来源 | 用户规模 × 体验/效率提升 | 信号优势 × 资金规模 − 交易成本 | 有效算力产出（tokens/GPU/$） |
| 收益形态 | 业务增量 → 人力预算 | PnL → 分成 | 成本节约 + 稀缺能力供给 |
| 边际收益 | 递减（规模效应有限） | 幂律（少数人贡献大部分 PnL） | 周期性 + 稀缺（供给长期不足） |
| 失败成本 | 低（可回滚、可灰度） | 极高（真金白银回撤） | 中高（一次千卡训练失败 = 数百万） |
| 对"正确性"的要求 | 可用即可，快速迭代 | 统计上必须站得住 | 数值与性能必须精确、可复现 |
| 组织特征 | 大团队、流程重、协作密度高 | 小而精、证据文化、信息隔离 | 中大型平台团队 + 极少数顶尖个人 |
| 晋升依据 | 业务结果 + 影响力 + 带人 | **PnL 归因份额** | 可量化的效率提升 + 不可替代性 |
| 收入曲线 | 前期平稳，后期靠职级 | 高方差、幂律、幸存者偏差大 | 中高起步，随稀缺度陡升 |

**三条关键推论：**

1. **互联网培养"系统构建者"，量化培养"证据驱动的决策者"，AI Infra 培养"极致性能的工程专家"。** 这是三种不同形状的人。跨行业迁移的难度，本质上取决于你这三种"形状"里哪一种更接近目标行业。
2. **量化是三者中唯一"结果不可伪造"的行业。** 因子能不能赚钱，市场直接投票。因此量化从面试到晋升，最看重的是**可验证的独立贡献**，而不是"参与过什么大项目"。这也是互联网背景最容易误判的地方——在互联网，"我参与了日活千万的系统"是有效叙事；在量化，这只说明你是颗螺丝钉，除非你能说清自己在那套系统里贡献了哪个具体的、可归因的部分。
3. **AI Infra 是三者中唯一"知识半衰期短于能力半衰期"的行业。** 需要澄清一个常见误读：AI Infra 的折旧**不是框架换代**（Megatron Core 至今是万亿参数训练的工业标准之一，与 DeepSpeed/FSDP 是并存路线，不是前代后继），而是**并行范式的收敛**——"切状态"（ZeRO/FSDP）与"切模型"（TP/PP/EP）两条线在 2023 年后合成 3D/4D 并行，随后又被 MoE 与大 EP 重塑。真正折旧的是"单卡视角的调参经验"和"某个框架的 API 用法"，不折旧的是体系结构、集合通信、编译原理、性能分析方法论。**所以护城河必须建在原理层，建在框架层的经验会周期性清零。**

**一个被忽略的连通事实**：幻方（High-Flyer）是 DeepSeek 的母公司。这不是八卦，而是本文核心结论的最强证据——**量化的高性能计算能力与 AI Infra 的能力是同一套东西的两个应用场景**。理解了这一点，第 7 节的迁移矩阵就不是推测，而是已经被验证过的路径。

## 2. 统一模型：能力四层 × 阶段五级

### 2.1 能力四层（跨行业通用坐标系）

任何技术工种的能力，都可以拆成四层。行业之间的差别不在于"层"不同，而在于**每层的权重**和 **L3 里装的是什么**。

```
L4 决策与杠杆层   技术选型 / 资源分配 / 组织与影响 / 风险定价
      ↑
L3 领域纵深层     行业 know-how：业务指标 / 统计与市场微观结构 / 硬件与编译
      ↑
L2 系统与工程层   分布式 / 并发 / 存储 / 网络 / 性能 / 稳定性 / 可观测
      ↑
L1 工具与语言层   语言 / 框架 / 调试 / CI / 规范
```

**各层权重（分析性估计）**

| 能力层 | 互联网 | 量化（QR） | 量化（QD） | AI Infra |
|---|---|---|---|---|
| L1 工具与语言 | 30% | 15% | 20% | 20% |
| L2 系统与工程 | 40% | 25% | 50% | 45% |
| L3 领域纵深 | 15%（业务理解） | 50%（统计/市场） | 20%（交易系统/低延迟） | 30%（硬件/编译/模型结构） |
| L4 决策与杠杆 | 15% → 后期 40% | 10% → 后期 40% | 10% → 后期 35% | 5% → 后期 35% |

**这张表能解释三个常见困惑：**

- 为什么互联网 P7 转量化"策略岗"极难，转"交易系统岗"相对可行？因为后者看 L2，前者看 L3，而 L3 无法迁移。
- 为什么 AI Infra 的顶级专家那么贵？因为它是三者中 **L3 门槛最高、且 L3 与 L2 耦合最紧**的方向——你要懂模型结构才知道该优化什么，要懂硬件才知道能优化到什么程度。
- 为什么互联网资深工程师容易"虚"？因为 L1+L2 占比 70%，一旦业务萎缩、系统规模不再增长，能力增长就停滞；而 L3/L4 没跟上，可替代性就暴露了。

### 2.2 阶段五级（跨行业统一语言）

| 阶段 | 统一含义 | 典型年限 | 核心跃迁 |
|---|---|---|---|
| **S1 执行者** | 把**任务**做对 | 0–2 年 | 从"学生"到"能独立交付" |
| **S2 独立贡献者** | 把**问题**做对 | 2–4 年 | 从"给方案就做"到"自己找方案" |
| **S3 领域 Owner** | **定义**问题 | 4–7 年 | 从"解决问题"到"选择问题" |
| **S4 方向负责人** | 定义**方向** + 带人 | 7–10 年 | 从"技术最优"到"综合最优"（成本/时间/人） |
| **S5 行业级影响** | 定义**标准/资源** | 10 年+ | 从"公司内"到"行业内" |

**最重要的判断：S2 → S3 是三个行业共同的最大分水岭。**

S1→S2 靠努力就能过（多做、多踩坑）。S2→S3 靠的是**判断力**——在没有明确需求文档的情况下，自己判断"什么值得做"。这一步过不去的人，会在 S2 停留 5–8 年，然后被行业周期淘汰。三个行业淘汰的机制不同，但淘汰的位置是同一个。

S3 之后，三个行业**分岔最厉害**：

- 互联网：往"技术管理"或"架构专家"两极分化，中间地带最危险（见 §3.4）
- 量化：往"被写进归因表的人"或"不可替代的基础设施专家"两极分化，金字塔极陡
- AI Infra：往"端到端性能/成本负责人"或"某一层的世界级专家"（编译器、通信、算子），中间层被平台化吃掉

## 3. 互联网研发序列

### 3.1 岗位分化（决定了你 S3 之后的天花板）

| 方向 | 典型岗位 | S4/S5 天花板 | 周期性 |
|---|---|---|---|
| 业务研发 | 后端 / 前端 / 客户端 | 中（受业务生命周期限制） | 强（跟业务涨落） |
| 基础架构 | 中间件 / 存储 / 计算 / 网络 | 高（但 **2022–2025 处于收缩期**） | 中，且当前偏弱 |
| 稳定性与效率 | SRE / 性能 / 成本优化 | 高（成本优化是永续需求） | 弱 |
| 数据与算法 | 数据平台 / 推荐 / 搜索 / 广告 | 高（广告/推荐是现金牛） | 中 |
| 安全 / 风控 | 攻防 / 反作弊 / 合规 | 中高 | 弱 |

**必须知道的一个反直觉事实**：互联网基础架构岗在**收缩**。2022 年以来的降本周期里，自研中间件/存储/RPC 框架被合并或替换为云产品，一个 200 人的基础架构团队缩到 30 人是常见操作。"天花板高"和"HC 在消失"可以同时成立——**对个人来说，HC 比天花板更重要**。

**选方向的核心原则**：优先选"**与公司现金牛强相关 + 技术深度可累积**"的方向。广告/推荐/搜索（离钱近）、稳定性与成本优化（离成本近）是两个长期安全区。纯业务 CRUD 方向在业务成熟后会被平台化压缩。

### 3.2 阶段路线图

| 阶段 | 年限 | 核心任务 | 能力要求 | 标志性产出 | 常见卡死原因 |
|---|---|---|---|---|---|
| S1 | 0–2 | 独立完成需求 | 语言熟练、调试、代码规范、Git/CI、单测 | 独立上线若干需求，无重大事故 | 只求"跑通"，不写测试、不看监控 |
| S2 | 2–4 | 负责一个模块/服务 | 分布式基础（缓存/MQ/DB 索引/幂等）、压测、灰度、链路追踪 | 一个服务的 owner，能定位线上问题 | 停留在"业务翻译"，不懂底层原理 |
| S3 | 4–7 | 负责一个子系统/领域 | 架构设计、容量规划、成本意识、跨团队协作 | 主导一次架构升级 / 大促保障 / 成本下降 | 只会"做技术"，不会"算账"和"对齐人" |
| S4 | 7–10 | 技术方向 + 团队 | 技术规划、资源分配、组织建设、向上管理 | 带 5–20 人团队或负责一条技术线 | 用"技术最优"代替"业务最优" |
| S5 | 10+ | 组织/行业影响 | 战略判断、行业标准、人才梯队 | 技术委员会 / 首席 / 总监级 | 只在大厂内部循环，没有行业话语权 |

### 3.3 时间与薪资锚点（经验区间）

| 阶段 | 典型职级（跨公司映射，近似） | 年包区间（万元） | 备注 |
|---|---|---|---|
| S1 | 阿里 P5 / 腾讯 T9 / 字节 2-1 | 25–45 | 校招主力区间 |
| S2 | P6 / T10 / 2-2 | 40–80 | 分水岭，3 年内没到 S2 要警惕 |
| S3 | P7 / T11 / 3-1 | 70–150 | 涨幅主要来自股票与绩效 |
| S4 | P8 / T12 / 3-2 | 120–250 | 开始有"管理溢价"或"专家溢价" |
| S5 | P9+ / T13+ / 4-1+ | 250–500+ | 极少数；含期权兑现波动 |

> 职级映射在不同公司、不同年份差异很大，只能用于粗略定位。判断自己位置时，**用"市场愿意给你什么 offer"校准，而不是用公司职级自我安慰。**

### 3.4 互联网特有的三个陷阱

1. **"35 岁问题"的真实机制**：不只是"能力结构老化"，更是两条硬约束——① **薪资年龄性价比**：一个 P7 的成本约等于 2–3 个 P6，当业务不需要"跨团队推动"这种高阶能力时，性价比立刻倒挂；② **位置稀缺**：社招 P7+ 的 HC 极少，很多 35+ 的人不是"能力不够"，而是"没有坑"。所以"建 L3/L4"是**必要但不充分**条件，还需要在 30 岁前后就开始经营"可带走的资产"（开源、行业影响力、跨公司人脉）。
2. **组织变动风险**：互联网组织调整频率高（半年一次很常见），"跟着老板走"的策略风险很大。应对方式是积累**跨组织可验证的资产**：开源项目、技术方案文档、行业分享、可量化的业绩数字。
3. **晋升通胀**：大厂职级持续通胀，同样的 P7，5 年前和现在的实际要求不同。

**互联网与另外两个行业最大的结构性差异**：互联网的晋升与**业务增量**强绑定。业务高速增长期，晋升周期可压缩到 2 年一级；业务停滞期，同样能力可能 5 年不动。**所以"选对业务"的重要性不低于"提升能力"。** 量化与 AI Infra 更依赖个人可量化的产出（PnL 份额 / 效率指标），受所在团队景气度影响相对小——但**都受行业资本周期影响，AI Infra 因为多属成本中心，在降本周期里反而先被砍**。

## 4. 量化

### 4.1 机构类型（决定了工作内容差异极大）

| 类型 | 代表形态 | 工作特征 | 对工程师的要求 |
|---|---|---|---|
| 私募量化（股票） | 高频/中频 alpha、指增、中性 | 因子研究 + 组合优化，PnL 归因清晰 | 统计功底 + 工程能力双高 |
| 私募量化（CTA/期货） | 趋势/套利 | 时序建模 + 风控，容量大、夏普低 | 时序统计 + 稳健性 |
| 高频做市 | 期权/期货 | 微秒级延迟、撮合、库存管理 | C++/内核/FPGA 极强 |
| 券商自营 / 资管 | 中性、指数增强 | 合规约束多、容量导向 | 工程规范 + 组合管理 |
| 公募量化 | 指增、量化对冲 | 相对收益、跟踪误差约束 | 组合优化 + 风控 |
| 加密量化 | 永续/现货套利、做市 | 7×24、基础设施粗糙、机会多、无竞业 | 全栈 + 快速迭代 + 抗压 |

**一个必须知道的行业格局事实**：2021 年以来，A 股量化的**超额收益系统性衰减**（以中证 500 指增为例，2021 年前后年化超额 20%+，近年收敛到个位数区间）。规模是超额的敌人——百亿级私募的超额显著低于十亿级。这有两个含义：① "进大机构、管大资金"不一定是最优选择；② 这个行业**不是单调向上的**，入行时点很关键。

### 4.2 三条职业轨道（分叉在入职时，不在 S2 之后）

- **QR（Quant Researcher，策略研究）**：产出是信号/因子/策略。核心能力是统计推断、市场直觉、过拟合识别。终点是 PM（管钱）。
- **QD（Quant Developer，系统开发）**：产出是回测引擎、交易系统、数据平台。核心能力是低延迟、分布式、数据工程。终点是基础设施负责人/技术合伙人。
- **Trader（交易员）**：产出是盘中执行与风险处置。国内纯 Trader 岗少，多与 PM 合一。

**关于"能不能互换"（这一条很多文章讲错）**：分叉基本在**入职时**发生，校招就分流。而且方向是**不对称**的——**QD → QR 在中低频是可行的**（研究栈是 Python + 统计，补得动）；**QR → QD 几乎不发生**（现代 C++、内存模型、内核、网络栈需要 3–5 年真刀真枪）。所以如果你还没决定，**先做 QD 是更安全的默认选项**。

**关于"QD 天花板低"**：这只在**工作室型小私募**成立（QD 是无分成的支持岗）。在**平台型机构**（幻方、九坤、明汯这类），技术负责人/CTO 在决策层，平台 QD 与策略团队是联合署名关系，天花板与 PM 同级。

### 4.3 阶段路线图（QR 轨）

| 阶段 | 年限 | 核心任务 | 能力要求 | 标志性产出 | 常见卡死原因 |
|---|---|---|---|---|---|
| S1 | 0–2 | 跑通因子流水线：清洗 → 挖单因子 → 回测 → 入库 | 概率统计、时间序列、Python/C++、回测框架 | 能独立跑通闭环，并说清一个因子的 **IC 为什么衰减** | 只会调库，不懂统计假设；把"跑通"当"做好" |
| S2 | 2–4 | 独立因子/信号，进入归因表 | 多重检验、样本外验证、交易成本建模、因子正交化 | 一个**上线并稳定贡献、被写进归因表**的因子 | in-sample 漂亮、live 失效（过拟合） |
| S3 | 4–7 | 独立策略线 / 组合 | 组合优化、风险预算、容量分析、风格归因 | 对一条策略线的**净值**负责 | 从"单策略"跨不到"组合与资金分配" |
| S4 | 7–10 | PM / 策略负责人 | 资金曲线管理、团队流程、风险偏好设定 | 管数亿至数十亿资金，团队可复现产出 | 个人能力强但无法"复制自己" |
| S5 | 10+ | 合伙人 / CIO | 资本配置、机构治理 | 机构级业绩记录 | 极少数 |

**QR 的真实分水岭不是"能不能管钱"，而是三级递进（很多人卡在第一级一辈子）：**

1. **被写进 PnL 归因表**——从"交因子"变成"我的因子贡献了多少"。多数人终身停在"因子供应商"，按归因份额分钱，不按 AUM 分钱。
2. **策略提案权**——能决定"下一季度研究什么方向"。
3. **Capital Allocation**——能给策略分资金。拿到**独立账户**通常在 **5–8 年**，且是少数人。

这个行业金字塔极陡：一个 30 人的研究团队，可能有 25 人终身停在 S2/S3。这不是能力问题，是**行业结构问题**——PnL 幂律分布决定了只有少数策略线值得配资金。

### 4.4 阶段路线图（QD 轨）

| 阶段 | 年限 | 核心任务 | 能力要求 | 标志性产出 |
|---|---|---|---|---|
| S1 | 0–2 | 维护回测/数据管道 | C++/Python、Linux、基础数据结构 | 修 bug、加功能、跑通链路 |
| S2 | 2–4 | 负责一个系统模块 | 低延迟编程、内存管理、网络协议、行情接入 | 一个模块的性能达标（延迟、吞吐） |
| S3 | 4–7 | 负责交易系统/数据平台 | 系统架构、故障恢复、容量规划、与策略方对齐 | 系统支撑 AUM 翻倍而不重构 |
| S4 | 7–10 | 基础设施负责人 / 技术合伙人（平台型机构） | 技术选型、团队、与 PM 协作 | 平台成为机构竞争力的一部分 |

QD 的天花板在平台型机构并不低，但**方差小得多**：不承担 PnL 风险，技能可迁移到 AI Infra、高频交易、芯片与交易所技术岗。

### 4.5 招聘漏斗（比能力更重要：入口决定成败）

这一节是本文最"现实"的部分，也是最容易被忽略的：

- **实习是 QR 的唯一常规入口。** 头部私募的 QR 岗一年收数千份简历 → 笔试（数学/概率/coding）→ 3–5 轮（现场 coding + 概率统计 + 研究讨论）→ **2–3 个月实习** → 转正率约 15–30%。**社招 QR 近乎不存在**（除非你有公开可验证的业绩或顶级竞赛/论文）。
- **QD 的入口宽松一些**：社招常见，看重 C++/系统能力，名校/科班滤镜比 QR 弱得多。
- **内推与"圈内可见度"权重极高**：量化圈子小，一个人能不能进，往往取决于"有没有人认识你"。这也是为什么第 9 节讲"作品集"时，量化那一栏要特别处理。

**推论**：如果你想转量化但还在读书/刚工作，**争取实习 > 刷题 > 自学**；如果已工作 5 年以上，**先走 QD 或加密量化**是现实得多的路径。

### 4.6 资金、归因与分成（"管钱"的真实含义）

- **配资逻辑**：新策略的资金 = f(**容量 × 夏普 × 与现有组合的相关性**)。上来就管几个亿是不存在的，先给 **500 万–2000 万验证仓**跑 3–6 个月。
- **分成结构**：PnL × 比例（常见 10–30%）× **归因份额**，普遍带 high-water mark。所以"我在一个赚钱的团队"和"我分到了钱"是两件事。
- **策略生命周期**（决定你必须持续产出）：中低频因子 **1–3 年**、高频 **6–18 个月**、加密 **3–6 个月**。因子库年更新率是核心 KPI。**"上线即衰减"比"上线难"更残酷。**

### 4.7 薪资锚点（经验区间，含分成后波动极大）

| 岗位/阶段 | 年包区间（万元） | 备注 |
|---|---|---|
| QR 校招 | 40–120（头部含签字费可到 150） | 极看学历与竞赛 |
| QD 校招 | 40–90 | 略低于 QR，但更稳 |
| QR 3–5 年 | 100–300 | 含分成的差异极大 |
| QD 3–5 年 | 70–150 | 方差小 |
| PM / 策略负责人 | 300 至千万级 | 极少数，与 PnL 直接挂钩 |
| 加密量化 | 现金低于传统私募，但分成比例高 | 无竞业、可远程 |

### 4.8 量化的四个硬约束（很多人低估）

1. **统计严谨性是入场券，不是加分项。** 面试会直接问：怎么做多重检验校正？样本外怎么切？如何判断一个因子是真 alpha 还是挖掘偏差？答不上来，工程能力再强也进不去 QR。
2. **回测不是实验，是观察性研究。** 它是单样本、非平稳、带选择偏差的事后拟合，没有随机化、没有对照组。互联网的 AB 实验经验能迁移的只有一条纪律——**先定指标再看数据**——除此之外的方法论几乎全部要重建。这是"互联网→量化策略"最大的认知陷阱。
3. **信息隔离与竞业是隐性成本。** 更准确地说：**PnL 记录归属机构，个人带不走**。这意味着你的成果难以公开、难以形成个人品牌、跳槽窗口受限、职业可逆性差（离开量化后很难回去）。这是量化最贵的隐性成本。（例外见下条）
4. **反馈周期长，且考核周期比策略验证周期短。** 中低频策略从想法到上线 3–9 个月，高频 2 周–2 个月；而机构容忍期通常只有 3–6 个月。**"考核短于验证周期"是量化研究员离职的第一大原因**，比"心理素质"具体得多。

**关于"量化无法公开业绩"的唯一例外**：**加密量化是量化中透明度最高的子行业**——部分账户/策略可被链上或公开托管账户第三方验证，且无牌照、无竞业、资金门槛低、可远程。对互联网/AI Infra 工程师来说，这是**摩擦最小的量化入口**，也是唯一能积累"可公开验证业绩"的路径。代价是：基础设施粗糙（限频、断连、插针）、7×24、机构化程度低。

## 5. AI Infra

### 5.1 八个细分方向（能力栈与就业面差异极大）

| 方向 | 核心问题 | 关键技术 | 就业面 / 护城河 |
|---|---|---|---|
| **训练 Infra** | 千卡/万卡如何高效稳定训练 | 3D/4D 并行（DP/TP/PP/EP）、集合通信（NCCL/DeepEP）、显存管理、容错恢复、checkpoint | 面最大；最吃分布式 |
| **推理 Infra** | 如何用更低成本服务更多请求 | Serving 框架、continuous batching、KV Cache、PD 分离（DistServe/Mooncake）、KV 池化（LMCache）、量化（INT8/FP8/FP4）、投机解码 | 面最大；最吃端到端优化 |
| **编译器** | 如何自动生成高效代码 | MLIR/TVM/XLA、图优化、算子融合、自动并行 | 面小、护城河最深 |
| **算子与 Kernel** | 如何把单个算子写到硬件极限 | CUDA/Triton、FlashAttention 级实现、通信算子 | 面小、护城河深；与编译器是**两个不同的招聘画像** |
| **集群可靠性与 Fleet Ops** | 万卡如何不宕、宕了如何快速恢复 | 慢节点检测、NCCL hang 定位、静默数据损坏（SDC）、日检、健康检查 | **互联网 SRE 唯一的真落点** |
| **平台与调度** | GPU 如何池化并高效分配 | K8s、GPU 共享/隔离、配额与弹性、MLOps、实验管理 | 最接近互联网基础架构，迁移成本最低 |
| **RL / Agent Infra** | 如何高效做 rollout 与环境交互 | 异步推理、rollout 引擎、环境沙箱、轨迹存储 | 2025–2026 最热，人才最缺 |
| **硬件协同 / 国产卡适配** | 如何在新硬件上跑起来 | 芯片架构、互联拓扑、算子手写迁移、精度对齐 | 稀缺但**多为支撑岗**，天花板反而不高 |

**选方向的判断**：训练与推理是大就业池（岗位多、可跳槽）；编译器/算子是最深护城河（人少、溢价高、但坑位极少）；集群可靠性是互联网 SRE 的最佳迁移落点；平台调度是"最像互联网"的方向（转型成本最低，但可替代性也最高）；国产卡适配要谨慎——它更像"交付/支撑"，性能常只有原厂 30–50%，工具链与社区都弱。

### 5.2 阶段路线图

| 阶段 | 年限 | 核心任务 | 能力要求 | 标志性产出 | 常见卡死原因 |
|---|---|---|---|---|---|
| S1 | 0–2 | 实现/优化一个模块 | CUDA 基础、PyTorch 内部机制、profiling（nsys/ncu）、Python/C++ | 一个算子加速 X 倍 / 一个 serving 特性上线 | 只会"调 vLLM 参数"，不懂为什么快 |
| S2 | 2–4 | 负责一个子系统 | 端到端瓶颈定位、SLO 定义、成本核算、分布式调试 | 推理集群吞吐提升 20–30% / 训练有效吞吐提升 10–15% | 只做局部优化，没有全局视角 |
| S3 | 4–7 | 端到端性能/成本负责人 | 跨层优化（模型-框架-系统-硬件）、路线选择、跨团队推动 | 单位 token 成本降一半 / 支撑模型规模翻 10 倍 | 不敢做取舍（如牺牲精度换吞吐） |
| S4 | 7–10 | 平台/技术方向负责人 | 技术战略、开源影响力、组织 | 一条技术路线成为公司标准 | 只在小圈子，无行业影响力 |
| S5 | 10+ | 技术战略 / 首席 | 行业标准、生态 | 定义某个方向的事实标准 | 极少数 |

### 5.3 真正的 KPI 是什么（别用 MFU 自我安慰）

| 层面 | 正确的指标 | 陷阱 |
|---|---|---|
| 训练 | **goodput**（有效训练时长占比）、线性度（scaling efficiency）、MTTR、**失败重算率** | MFU 跨模型/序列/集群不可比，**缩小模型就能刷高**，是最容易被误用的指标 |
| 推理 | tokens/s/GPU、$/1M tokens、P99 延迟、KV Cache 命中率 | 只看吞吐不看 P99，线上会被长尾打死 |
| 编译/算子 | 算子加速比、端到端收益（不是单算子收益） | 单算子快 2 倍，端到端快 3% 是常态 |
| 可靠性 | 可用性、故障定位时长、MTBF、日均人工介入次数 | 没有告警驱动，靠 owner 自己盯 |

**"过 S2 靠贴数字，过 S3 靠证明这个数字是你带来的。"** AI Infra 是三个行业里最"数字说话"的，甚至比量化更直接——量化至少还有运气成分，AI Infra 的性能提升是可复现的。这对不擅长组织政治、喜欢纯粹工程的人是巨大优势；但也意味着**做"平台维护"型工作的人很难升**。

### 5.4 推理优化的真实 ROI（企业视角 ≠ 个人护城河）

这是内行与外行差距最大的一张表：

| 手段 | 典型收益 | 投入 | ROI |
|---|---|---|---|
| 选对模型 / 蒸馏 | 数量级 | 低 | 最高（但属算法侧） |
| 量化（INT8/FP8）+ KV Cache 优化 | 2–3x | 1–2 人月 | **最高（工程侧）** |
| Prefix / KV 复用 | 命中率高时 1.5–2x | 中 | 高（依赖流量特征） |
| PD 分离 | 大规模下 1.3–1.8x | 高 | 中（小规模不划算） |
| 投机解码 | 通用 1.2–1.5x | 中 | 中 |
| 自研 kernel | 除 FA 级团队外常为负 ROI | 很高 | 低 |

**结论**：企业 80% 的推理成本优化来自"选模型 + 量化 + 缓存"，而不是"写 kernel"。但**个人的护城河恰恰在低 ROI 的那几行**——因为 ROI 低 = 门槛高 = 会的人少。**要分清"公司该做什么"和"你该会什么"，这是两件事。**

### 5.5 AI Infra 的特殊性

**① 岗位来源极少，入口是硬约束。** 全国范围内，AI Infra 的岗位只来自四类地方：大厂（Seed/PAI/混元/通义这类）、明星创业公司、云厂商、芯片公司的软件栈团队。一个团队一年可能只有 2–5 个 HC，**社招几乎不吃投递，靠内推与开源可见度**。所以"技能匹配"只是必要条件，"有没有通道"往往才是决定因素。

**② 万卡集群的组织形态**：训练框架组 / 集群运维组 / 编译算子组 / 推理服务组 / 平台产品组，外加**嵌入模型团队的 Infra 人**（最有效、最稀缺的形态）。**抢卡配额是组织权力**——这一点互联网出身的人要有心理准备：技术方案再好，没有配额也做不了。

**③ on-call 文化与互联网相反**：互联网故障是"降级、止损、恢复"；AI Infra 故障是"几百张卡白烧 + 一周进度回滚"。典型故障是 **NCCL hang（无报错，只看利用率归零）**、慢节点、SDC、checkpoint 写爆存储。没有成熟的告警体系，靠 owner 自己盯 + 数天长尾排查。这对"习惯告警驱动"的互联网工程师是真实的落差。

**④ 知识半衰期的应对**：学习预算按 **7:2:1** 分配——70% 投在不变的底层（体系结构、通信、编译、操作系统、性能分析方法论），20% 投在当前主流框架，10% 投论文与新硬件。**只投后 30% 的人，会在下一次技术换代时被清零。**

### 5.6 薪资锚点（注意双轨制）

| 阶段 | 大厂职级轨（万元/年） | 明星创业公司轨 | 备注 |
|---|---|---|---|
| S1 | 30–55 | 25–40 现金 + 期权 | 大模型方向校招显著高于普通后端 |
| S2 | 55–110 | 40–70 现金 + 期权 | 稀缺方向（编译/通信/推理优化）同级溢价 **50–100%** |
| S3 | 100–200 | 80–150 + 期权 | 头部创业公司核心 Infra 可达 200–400 |
| S4 | 180–350+ | 期权为主 | 平台负责人 / 知名开源 maintainer |
| S5 | 300–600+ | 股权 | 极少数 |

> 双轨不能混在一个区间里比：大厂是"高现金 + 低期权"，创业公司是"低现金 + 高期权"。**比较时请用期望值，并给期权打一个你信得过的折扣。**

## 7. 能力迁移矩阵（本文核心）

**读法**：★★★ = 决定性，★★ = 重要，★ = 加分项。注意：**这一节的复用率是"能力可迁移比例"，不是"转行成功率"**——后者主要由入口机制（实习/内推/开源可见度）决定，见 §8。

| 能力项 | 互联网 | 量化 | AI Infra | 迁移说明 |
|---|---|---|---|---|
| 分布式系统设计与调试 | ★★★ | ★★ | ★★★ | 表面通用，**但故障域相反**：互联网是异步/请求级/无状态/加机器可解；AI Infra 是同步/集合通信/拓扑感知/固定资源榨干，坏卡是常态。方法论可迁移，直觉要重建 |
| 高性能/低延迟优化 | ★★ | ★★★ | ★★★ | 量化与 AI Infra 的公共语言（cache、SIMD、锁、NUMA、profile）。互联网出身普遍偏弱，是迁移最大缺口之一 |
| 数据管道与数据质量 | ★★ | ★★★ | ★★★ | 量化叫"数据清洗与对齐"，AI Infra 叫"语料工程"，本质同一件事。迁移成本低 |
| 统计推断与实验设计 | ★★★（AB/因果） | ★★★（**但回测是观察性研究，不是 AB**） | ★（多为工程验证） | 可迁移的只有"先定指标再看数据"的纪律；多重检验、非平稳、生存偏差要重建 |
| 机器学习/深度学习 | ★★ | ★★ | ★★★ | AI Infra 需要"懂模型才能优化模型"，这是硬门槛 |
| GPU/算子/编译 | ★ | ★★（训练自有模型） | ★★★ | 从零建立需 1–2 年系统投入，是 AI Infra 的核心壁垒 |
| 系统稳定性与可观测 | ★★★ | ★★（交易时段零容忍） | ★★★ | **不要高估**：DCGM 粒度很粗，NCCL hang 与 SDC 几乎没有内省手段，AI Infra 的可观测性是"原始"的 |
| 成本核算与容量规划 | ★★ | ★★（容量=策略约束） | ★★★ | AI Infra 里"成本"就是核心 KPI，互联网的成本优化经验可直接复用 |
| 业务/市场理解 | ★★★ | ★★★（市场微观结构） | ★（模型能力边界） | **最不可迁移**。量化的市场理解只能在市场里长出来 |
| 数学建模与优化理论 | ★ | ★★★（组合优化/随机过程） | ★★（并行策略/调度） | 量化要求最高；AI Infra 的优化偏工程而非理论 |
| 工程规范与协作 | ★★★ | ★★（小团队，规范弱） | ★★ | 互联网最规范，迁移过去是加分项（能显著提升量化/AI Infra 团队工程水位） |
| 技术判断与路线选择 | ★★ | ★★ | ★★★ | S3 之后的核心能力，三行业通用 |

### 7.1 迁移"复用率"速查（能力维度，非成功率）

| 迁移方向 | 可复用能力占比（估） | 主要缺口 | 现实难度 |
|---|---|---|---|
| 互联网 → AI Infra | **50–60%** | GPU/算子/编译、模型内部机制、同步并行的直觉 | ★★★ |
| 互联网 → 量化（QD/交易系统） | **40–50%** | 现代 C++ 深度、低延迟、行情/撮合领域知识 | ★★★ |
| 互联网 → 量化（QR/策略） | **10–20%** | 统计严谨性、市场理解、过拟合识别；且**入口几乎只有实习** | ★★★★★（3–5 年，成功率 <20%） |
| AI Infra → 量化（QD/低延迟） | **40–50%** | 交易领域知识、金融风控；且多数人不写低延迟 C++ | ★★★★ |
| AI Infra → 量化（QR） | **25–35%** | 统计、市场、策略思维 | ★★★★★ |
| 量化（QD）→ AI Infra | **40–50%** | 分布式规模（量化系统通常小 1–2 个数量级）、模型知识 | ★★★ |
| 量化（QR）→ AI Infra | **30–40%** | 系统工程深度、GPU 栈 | ★★★★（数学强是优势，工程要从头补） |

**一句话总结**：**"系统与工程能力"（L2）在三者之间迁移性最好；"领域纵深层"（L3：市场理解 / 硬件编译 / 业务 know-how）迁移性最差。所以跨行业迁移的最佳策略永远是"用可迁移的 L2 换赛道，再在目标行业补 L3"。**

**但请记住第二条**：**复用率 50% 不等于成功率 50%。** 量化看实习与本科学历，AI Infra 看内推与开源可见度，互联网看业务匹配。**入口机制比能力匹配度更决定成败**——这是本文最重要的一句实践建议。

## 8. 五条迁移路径（含时间成本、第一步与真实门槛）

### 路径 A：互联网后端 → AI Infra（推荐度最高）

- **时间成本**：12–18 个月达到"能干活"，24 个月达到目标行业同级水平。
- **为什么顺**：分布式、稳定性、成本优化、大集群运维——方法论同一套。
- **要补的**：CUDA 编程（2 个月只够"跑通"，优化要 6 个月以上）、PyTorch 内部机制与显存管理（2 个月）、推理/训练全链路（3 个月）、nsys/ncu 性能分析（2 个月）。
- **第一步**：读 vLLM 或 SGLang 的 scheduler 与 KV Cache 实现，**提 issue + 复现 bug + 交 benchmark 报告**（注意：给核心框架提 PR 极难 merge，一开始的目标应该是"能被人看见的贡献"，不是 merge）。
- **真实门槛**：**你个人拿不到千卡**。所以能不能进 AI Infra，最大的隐形门槛不是技能，而是"有没有内部转岗的机会"或"有没有人内推"。**先在公司内部找 Infra 相关需求（推理成本优化、训练加速），是最省力的跳板。**

### 路径 B：互联网 → 量化 QD（交易系统/数据平台）

- **时间成本**：12–18 个月。
- **要补的**：现代 C++ 与内存模型（3 个月）、Linux 内核与网络栈（3 个月）、行情/撮合/风控领域知识（6 个月，只能在项目里学）。
- **第一步**：用 C++ 写限价单簿 + 撮合引擎，做到**端到端 20–50μs**（注意：单机自研 demo 含网络与内核，10μs 是不现实的目标），配 **DPDK/内核旁路收包 demo + 延迟分布图**。这是面试最有效的敲门砖。
- **真实门槛**：**没有真实行情与撮合环境，自学天花板很低**。所以最优路径往往是"先进中小私募/加密量化做系统，再跳平台型机构"。另外，"名校过滤器"对 QR 很硬，对 QD 松得多。

### 路径 C：量化 → AI Infra（训练/推理平台）

- **时间成本**：12–18 个月。
- **为什么可行**：量化的高性能计算、数据处理、严谨工程习惯在 AI Infra 极受认可；很多 Infra 团队缺"能把系统做得又稳又准"的人。
- **要补的**：分布式规模经验（量化系统通常几百核，AI Infra 是几千卡）、模型结构与训练流程、GPU 生态。
- **第一步**：复现一个 8 卡小规模并行训练并写出 scaling 分析报告；或参与开源框架的分布式模块。
- **风险**：有分成的量化岗收入可能高于 AI Infra 同级，短期可能降薪。

### 路径 D：AI Infra → 量化（低延迟方向）

- **时间成本**：18–24 个月。
- **为什么可行**：高频量化最缺"能把延迟压到极致"的工程师。
- **必须纠正的一个误解**：**高频交易的核心是网络栈、内核旁路、FPGA/专用硬件，CUDA 基本用不上**（除期权定价类场景）。真正对口的是"推理引擎 C++ 那一小撮"和高性能网络。等价地，你说的"收包 < 1μs"在常规内核栈上做不到——**合理目标是端到端 < 10μs，或 bypass 路径 < 2μs**。
- **要补的**：网络栈/DPDK/内核、交易领域知识、金融时间序列基础。
- **风险**：量化文化差异大（保密、高压、结果导向），职业可逆性差。

### 路径 E（隐形但常见）：降级跳 > 平级跳

**跨行业迁移时，"降一级进入、两年内追平"的成功率显著高于"平级进入"。** 因为行业 L3 缺口是真实的，硬要平级进入会在前 6 个月暴露，然后被贴上"名不副实"的标签。**用职级换赛道，是这三个行业之间最划算的交易。**

## 9. 时间与复利：1 / 3 / 5 / 10 年检查点

### 9.1 三行业的"复利曲线"形状不同

| 行业 | 曲线形状 | 含义 |
|---|---|---|
| 互联网 | **阶梯形**（随业务与职级跳变） | 需要在关键节点"押对业务"；平缓期要靠 L3/L4 积累避免停滞 |
| 量化 | **前陡后幂律**（前 3 年收入与信息密度陡升，**停滞的是职级与 PnL 份额**） | 需要在 S2→S3 之前判断自己是否可能进入归因表；进不去要提前准备退路 |
| AI Infra | **指数形**（底层能力持续增值，框架知识周期性折旧） | 越早建底层越好；35 岁后反而是优势行业 |

### 9.2 检查点（自检用）

**第 1 年（S1 末）**
- 互联网：能否独立交付一个中等需求并保证不出线上事故？
- 量化：能否独立跑通"数据→因子→回测→入库"闭环，并解释 IC 为何衰减？
- AI Infra：能否独立定位一个性能瓶颈并给出优化方案？

**第 3 年（S2 末）**
- 互联网：是否有一个"我负责的服务"？能否说清它的容量、成本、SLA？
- 量化：是否有因子/模块**上线并进入归因表**？
- AI Infra：是否有一个"我优化的子系统"，指标提升能落到具体数字（吞吐/成本/P99）？

**第 5 年（S3 中）**
- 三者共同标准：**是否有过一次"我自己定义问题并推动落地"的经历？** 没有，说明还在 S2。
- 互联网：是否能做技术选型并对结果负责？
- 量化：是否**被写进 PnL 归因表**（而不是"参与了一个赚钱的团队"）？
- AI Infra：是否能对一个端到端指标（成本/吞吐/goodput）负责？

**第 10 年（S4 末）**
- 共同标准：**离开当前公司，你的能力是否还能被市场以同级价格认可？**
- 量化额外：是否有可带走的业绩记录（注意：PnL 记录归属机构，能带走的是方法与声誉）？
- AI Infra 额外：是否有行业级影响力（开源 maintainer / 标准参与者 / 被引用的工作）？

### 9.3 投入配比建议（每年）

| 阶段 | 本职深度 | 相邻能力 | 探索/跨界 |
|---|---|---|---|
| S1 | 80% | 15% | 5% |
| S2 | 70% | 20% | 10% |
| S3 | 60% | 25% | 15% |
| S4+ | 50% | 25% | 25% |

**"相邻能力"是什么**：互联网的相邻是 AI Infra（工程栈上移）；量化的相邻是 AI Infra（GPU/训练）或数据工程；AI Infra 的相邻是模型算法（懂模型才能优化模型）。**这条 20% 的投入，就是未来跨行业迁移的期权。**

### 9.4 各行业的"作品集"长什么样

| 行业 | 有效的个人资产 | 无效的资产 |
|---|---|---|
| 互联网 | 开源项目、架构方案、可量化业绩（QPS/成本/稳定性） | "参与过 XX 亿级项目"（无法验证） |
| 量化 | 方法论输出（公众号/播客/开源框架如 Qlib 生态）、竞赛成绩、**加密量化的链上可验证业绩** | 简历上的"年化 XX%"（无法验证，且有合规风险） |
| AI Infra | 开源 PR（vLLM/SGLang/Megatron）、性能优化报告、技术博客 | "熟悉 XX 框架"（人人都会写） |

**共同点：能被第三方独立验证的东西才有价值。** 量化的特殊性在于——正因为大部分产出不可公开，**"能讲清楚方法论"本身就成了最强的可信信号**，也是量化招聘中真实存在的筛选维度。

## 10. 决策框架：怎么选

### 10.1 三个问题定方向

1. **你更享受"把系统做对"还是"把判断做对"？**
   - 前者 → 互联网基础架构 / AI Infra
   - 后者 → 互联网业务 / 量化
2. **你能承受多长的不确定期？**
   - < 6 个月 → 互联网（反馈最快）
   - 6–12 个月 → AI Infra（性能优化有明确指标）
   - > 12 个月 → 量化（策略验证周期长，且考核周期可能短于验证周期）
3. **你希望 10 年后的身份是什么？**
   - "某领域的技术专家" → AI Infra / 互联网架构
   - "能管钱的人" → 量化
   - "能带团队打硬仗的人" → 互联网管理

### 10.2 三行业的风险收益画像

| | 互联网 | 量化 | AI Infra |
|---|---|---|---|
| 期望收益 | 中 | 高 | 中高 |
| 收益方差 | 低 | 极高 | 中 |
| 下行风险 | 中年失业（结构性）+ 基础架构 HC 收缩 | 超额衰减 + 策略失效 + 机构倒闭 | 算力格局变化 + 架构突变 + 成本中心先被砍 |
| 上行天花板 | 中高 | 极高 | 高 |
| 适合的风险偏好 | 稳健型 | 激进型 + 强心理素质 | 稳健偏进取 |

### 10.3 组合策略（推荐给大多数人的方案）

不要"三选一"，而要"**主航道 + 期权**"：

- **主航道**（70–80% 精力）：选一个当下确定性最高的行业扎根，目标 3 年内到 S2/S3。
- **期权**（20–30% 精力）：持续投入"跨行业可迁移的底层能力"——分布式、性能优化、统计、GPU。这些在任何一条路上都不浪费。
- **触发条件**：当主航道出现结构性风险（业务萎缩、组织变动、行业下行），用期权切换，而不是从零开始。

**具体到当下的建议**：AI Infra 是三者中"稀缺度最高 + 年龄敏感性最低 + 与另外两者都有交集"的位置，且已由"幻方 → DeepSeek"这一事实证明了与量化的同源性。它可以作为主航道，也可以作为互联网/量化工程师的期权。**但要注意它的入口约束**——如果没有内部转岗或内推通道，硬转的成本很高；这种情况下，更现实的打法是"在本职岗位上主动接 Infra 相关的需求"，用项目经验换门票。

## 11. 十一个常见误区

1. **"量化就是数学好"** —— 数学是门槛，**归因份额**才是命门。IMO 金牌做不出 alpha 的人比比皆是。
2. **"AI Infra 就是会调 vLLM"** —— 调参是 S1 的工作。真正的价值在"为什么这样设计"和"如何再快 20%"。
3. **"互联网经验可以直接迁移到量化策略"** —— 工程能力部分可以，策略思维几乎不能。**回测是观察性研究，不是 AB 实验。**
4. **"刷题 = 能力"** —— 面试门槛 ≠ 工作能力。三者皆然。
5. **"早点转管理"** —— S3 之前转管理，会让你失去唯一的硬通货（技术深度），且管理岗方差更大。
6. **"大厂职级 = 市场价值"** —— 职级通胀 + 业务绑定，很多 P8 离开平台后拿不到同级 offer。
7. **"AI Infra 的框架知识是护城河"** —— 恰恰相反，框架是消耗品，原理才是资产。
8. **"量化赚得多所以更好"** —— 忽略了幸存者偏差、保密约束、职业不可逆（PnL 记录带不走）。
9. **"跨行业要平级跳"** —— 降一级进入、两年追平，成功率显著更高。
10. **"能力够了自然有机会"** —— 三个行业的入口都由机制决定：量化的实习、AI Infra 的内推与开源、互联网的业务匹配。**主动经营通道是能力的一部分。**
11. **"AI Infra 是成本中心所以稳定"** —— 恰恰相反，降本周期里成本中心的团队先被砍；它的稳定性来自"稀缺"，不来自"不可替代"。

## 12. 自检清单（每题 0–2 分，满分 40）

**工程能力（L1/L2）**
1. 我能独立定位一个线上性能问题并给出根因（而非猜测）。
2. 我能说清自己负责的系统的容量上限与瓶颈在哪。
3. 我做过一次"从 0 到 1"的系统设计并负责落地。
4. 我熟悉至少一种 profiling 工具并能读懂火焰图/算子级指标。

**领域深度（L3）**
5. 我的领域里，我能说出 3 个"外行不知道的坑"。
6. 我能判断一个技术方案在什么条件下会失败。
7. 我读过本领域至少 5 篇核心论文/规范，并能讲出它们的局限。

**判断力（S2→S3）**
8. 我主动发起过一个"没人要求我做"的项目并做成了。
9. 我做过一次"放弃"的决策（判断某事不值得做）。
10. 我能为自己的技术选择算清成本与收益。

**迁移能力**
11. 我有一项能力在至少两个行业都适用。
12. 我最近 12 个月学过一项"与当前工作无直接关系"的技能。
13. 我能把自己的经验抽象成方法论讲给别人听。

**影响力（L4）**
14. 我的技术方案被团队外的人采用过。
15. 我在公开场合（分享/开源/写作）输出过内容。
16. 我带过至少一个人成长。
17. 我能说服非技术的人接受我的技术判断。

**职业健康度**
18. 我知道自己所在业务/机构/技术路线的 3 个结构性风险。
19. 我有一份"离开当前公司也能用"的作品或记录。
20. 我能在 30 秒内说清"我最擅长什么、市场为什么需要它"。

| 得分 | 阶段判断 | 下一步重点 |
|---|---|---|
| 0–10 | S1 | 做对任务 + 建立学习习惯 |
| 11–20 | S2 | 从"解决问题"到"发现问题"，开始积累 L3 |
| 21–30 | S3 | 定义问题 + 影响他人，开始建立个人品牌 |
| 31–40 | S4 潜力 | 方向判断 + 组织杠杆 |

## 附录 A：12 个月行动计划（三条主路径）

### A1. 互联网 → AI Infra

| 季度 | 动作 | 交付物 |
|---|---|---|
| Q1 | CUDA 基础 + PyTorch 显存机制；读 vLLM scheduler / KV Cache 源码；用 ncu profile 一个 attention kernel | 一份 profiling 报告（瓶颈定位 + 优化前后的数字） |
| Q2 | 端到端部署 vLLM/SGLang，做压测（不同 batch/序列长度/量化配置） | 一份 benchmark 报告；给上游提 1–3 个 issue（复现 + 数据） |
| Q3 | 在公司内部主动接一个"推理成本/训练加速"相关需求 | 一个可量化的降本或提速案例（哪怕只有 10%） |
| Q4 | 内部转岗 / 内推 / 开源贡献 | 面试时能讲清"我让 X 的成本降了 Y%" |

**关键判断**：如果 Q3 拿不到内部 Infra 需求，说明通道不通，应转向"平台调度/集群可靠性"这类与现有 SRE 经验重叠度更高的子方向。

### A2. 互联网 → 量化 QD

| 季度 | 动作 | 交付物 |
|---|---|---|
| Q1 | 现代 C++（移动语义/模板/内存模型/无锁队列）；实现限价单簿 | 一个正确性可测的单簿实现 |
| Q2 | 撮合引擎 + 性能优化；DPDK 收包 demo | 端到端 20–50μs 的 demo + 延迟分布图 |
| Q3 | 行情协议、撮合规则、风控基础；数据管道 | 一个能跑通"行情→撮合→风控"的最小系统 |
| Q4 | 内推（中小私募/加密量化优先）+ 面试 | offer；若失败，先进加密量化积累真实环境经验 |

### A3. 转量化 QR（最难的一条，仅供评估）

| 季度 | 动作 | 说明 |
|---|---|---|
| Q1 | 统计推断 + 时间序列 + 随机过程系统补课 | 这一步会筛掉 70% 的人 |
| Q2 | 用 Qlib 复现 2–3 个经典因子，做样本外验证 | 重点不是收益，是**验证方法的严谨性** |
| Q3 | 回测框架 + 交易成本模型 + 多重检验校正 | 能解释"为什么我的因子是假的" |
| Q4 | 竞赛（Kaggle/量化比赛）或实习 | **没有实习，社招 QR 基本不成立** |

**坦率结论**：这条路需要 3–5 年，成功率 <20%，且高度依赖学历入口。**除非你已经在读相关硕博或有极强竞赛背景，否则不建议作为主路径。**

## 附录 B：岗位与团队甄别清单

### 面试时应该问的问题

**通用**
- 这个岗位的"成功"在 12 个月后如何衡量？具体指标是什么？
- 团队过去一年最大的技术决策是什么？谁做的？为什么？

## 附：一页纸决策摘要

- **三行业的本质差异**：互联网卖"系统 + 业务杠杆"，量化卖"可验证的边际 PnL"，AI Infra 卖"稀缺的工程深度"。
- **能力可迁移性排序**：系统与工程（L2）> 统计与优化（部分 L3）> 行业 know-how（L3，几乎不可迁移）。
- **迁移最优策略**：用可迁移的 L2 换赛道，**降一级进入**，2 年内补 L3 追平。
- **三条最可行的路径**：互联网→AI Infra（复用 50–60%）、互联网→量化 QD（40–50%）、量化 QD→AI Infra（40–50%）。
- **最难的一条**：互联网→量化 QR（复用 10–20%，需 3–5 年，且入口几乎只有实习）。
- **被低估的事实**：复用率 ≠ 成功率。入口机制（实习 / 内推 / 开源可见度）比能力匹配度更能决定成败。
- **时间锚**：S1→S2 约 2–3 年；S2→S3 约 3–5 年且是最大分水岭；量化拿到独立账户通常 5–8 年。
- **当下最划算的对冲**：把 20% 精力投到 GPU / 性能优化 / 分布式——这三项在三个行业都不贬值，且已被"量化 → DeepSeek"验证过同源性。
